PROMPT: Backend + IA + PDF para PRYSM
Contexto
PRYSM es una plataforma de asesoría de imagen personal. Las clientas hacen un quiz de 12 preguntas, suben fotos de su rostro (frontal, perfil), y reciben un informe personalizado en PDF sobre su temporada de color, estilo, cabello y outfits.

Stack actual:

Frontend: HTML/JS vanilla en /workspace/prysm-platform/index.html
Base de datos: Supabase (ya conectado)
Pagos: MercadoPago (ya conectado)
Análisis de foto: pixel-sampling básico con Canvas API — FAKE, no es IA real
PDF: solo preview HTML — NO existe PDF real generado
Flujo actual:

Landing → Quiz (12 preguntas) → Subir fotos → "Analizando..." → Preview → Pago $299 → Reporte (HTML)
Flujo deseado:

Landing → Quiz → Subir fotos → BACKEND: IA analiza foto → PDF real personalizado → Preview → Pago → Descarga PDF
Objetivo
Construir un Backend API en Node.js que:

1.
Reciba las fotos + respuestas del quiz desde el frontend
2.
Analice la foto con visión artificial real para determinar temporada de color
3.
Genere un PDF premium personalizado con los datos de la clienta
4.
Devuelva el PDF al frontend para que la clienta lo vea y descargue

Servicio 1: Análisis de Color (colorAnalysis.js)
Input: imagen (base64 o file) del rostro de la clienta Output: { skinColor, undertone, depth, contrast, saturation }

Cómo funciona — usar Canvas API para pixel sampling + algoritmo de colorimetría:

1.
Recibir imagen → cargar en <canvas>
2.
Definir región de muestra: forehead + both cheeks (evitar ojos, boca, cabello, fondo)
3.
Extraer pixels de la región → promediar R, G, B
4.
Convertir a HSL para análisis
5.
Determinar undertone:
Si R > B → warm
Si B > R → cool
Si diferencia < umbral → neutral
6.
Determinar depth (luminosidad):
L > 0.60 → light
L < 0.38 → deep
resto → medium
7.
Determinar saturación:
S > 0.5 → high
S < 0.25 → low
resto → medium
8.
Devolver valores + color hex del piel
Región de muestreo (la IA determina esto):

Cosas importantes
1.
No inventar datos. Todo el contenido del PDF debe venir de las respuestas del quiz o del análisis de la foto. Si una respuesta no está disponible, mostrar "No disponible" — nunca inventar.

2.
La foto de la clienta debe aparecer en la cover del PDF. Usar la foto que sube en el quiz.

3.
Tiempo de respuesta del análisis: Debe ser menor a 10 segundos. Playwright tarda ~3-5 segundos en generar el PDF. El análisis de color < 1 segundo.

4.
Manejo de errores: Si la foto no se puede analizar, fallback a determinar la temporada solo con las respuestas del quiz (skinTone + undertone del quiz).

5.
Limpieza: Eliminar fotos temporales después de generar el PDF (máximo 24 horas de retención).
