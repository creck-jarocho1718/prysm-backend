PROMPT MAESTRO — INTEGRACIÓN REAL DE OPENAI EN PRYSM

OBJETIVO PRINCIPAL

Quiero modificar PRYSM para que el resultado final del análisis de imagen personal sea generado REALMENTE por OpenAI GPT utilizando:

1. Las fotografías reales que sube el usuario.
2. TODAS las respuestas del test.
3. El análisis visual disponible de las fotografías.
4. La lógica de colorimetría, estilo, silueta, presupuesto y guardarropa.

NO quiero resultados predeterminados ni resultados hardcodeados.

MUY IMPORTANTE:
NO MODIFIQUES EL DISEÑO VISUAL ACTUAL DE PRYSM.
NO CAMBIES Landing, Quiz, animaciones, estructura visual del Report, estilos, tipografías, colores ni distribución.
Solo modifica la lógica y conexión de datos necesaria para conseguir el análisis real.

==================================================

==================================================

El flujo debe ser:

Landing
→ Quiz
→ Fotos

→ PDF

FOTOS + RESPUESTAS + DATOS DEL ANÁLISIS

REPORT Y PDF DEBEN UTILIZAR EXACTAMENTE EL MISMO RESULTADO.

NO volver a analizar al generar el PDF.
NO generar un segundo perfil para Report.
NO generar datos diferentes entre Report y PDF.

==================================================
2. OPENAI DEBE HACER EL ANÁLISIS REAL
==================================================

La IA debe recibir las fotografías reales del usuario mediante visión.

También debe recibir las respuestas completas del test.

Debe cruzar ambas fuentes.

NO debe limitarse a leer solamente las respuestas.
NO debe limitarse a analizar solamente las fotografías.

El resultado debe surgir de la combinación de:

- características visuales observables
- tono/subtono de piel observable
- profundidad de color
- contraste
- cabello y ojos cuando sean visibles
- respuestas del usuario
- silueta indicada en el test
- estilo deseado
- sensación que quiere proyectar
- ocasiones
- presupuesto
- colores que ya tiene
- prendas que ya tiene
- metal preferido
- arquetipo/look de referencia

==================================================
3. TEMPORADAS DE COLOR
==================================================

ESTÁ PROHIBIDO usar una temporada fija como resultado predeterminado.

NO utilizar:

"soft_autumn"

"deep_autumn"

"warm_autumn"

ni ninguna otra temporada como fallback automático.

GPT debe poder determinar cualquiera de las familias:

PRIMAVERA
VERANO
OTOÑO
INVIERNO

Y, cuando exista suficiente evidencia, una subestación correspondiente.

Ejemplos:

- Primavera Cálida
- Primavera Clara
- Primavera Brillante
- Verano Claro
- Verano Suave
- Verano Frío
- Otoño Cálido
- Otoño Suave
- Otoño Profundo
- Invierno Frío
- Invierno Brillante
- Invierno Profundo

NO elegir una temporada porque sea la más fácil de generar.

La temporada debe estar sustentada por las características observadas.

Si la evidencia visual no es suficiente para determinar una subestación con seguridad, devolver la familia de temporada y marcar la confianza como menor.

6. CÓMO DEBE USAR CADA RESPUESTA
==================================================

Q1:
Debe influir en la dirección estética y las recomendaciones.

Ejemplo:
Si quiere sentirse sofisticada:
priorizar líneas pulidas, elegantes y refinadas.

Si quiere sentirse natural:
priorizar texturas, siluetas y combinaciones relajadas.

Q2:
Debe utilizarse como información complementaria para el análisis de color.

NO debe sustituir automáticamente el análisis fotográfico.

Q3:
Debe determinar las recomendaciones de silueta.

Ejemplo:

Reloj de arena:
- enfatizar cintura
- equilibrar proporciones
- recomendar cortes que respeten curvas

Rectángulo:
- crear definición visual
- capas, volumen o estructura donde corresponda

Triángulo:
- equilibrar visualmente hombros y cadera

Etc.

Q4:
DEBE modificar las recomendaciones de compra.

Presupuesto bajo:
priorizar básicos versátiles, precio/uso y combinaciones.

Presupuesto medio:
mezclar básicos de buena calidad con piezas de inversión.

Presupuesto alto:
permitir piezas premium y de mayor inversión.

NO mostrar siempre las mismas recomendaciones independientemente del presupuesto.

Q5:
Analizar los colores existentes del clóset contra la paleta personalizada.

Para cada color importante indicar:

✓ CONSÉRVALO
→ porque armoniza con tu paleta.

⚠️ ÚSALO CONDICIONALMENTE
→ funciona mejor combinado con determinados colores.

✕ CONSIDERA REEMPLAZARLO
→ porque genera poco contraste/armonía según el análisis.

Q6:
Analizar las prendas que ya posee.

Separar:

YA TIENES Y TE FAVORECE
YA TIENES PERO COMBÍNALO ASÍ
TE FALTA
PRIORIDAD DE COMPRA

No recomendar comprar cosas que ya tiene si no son necesarias.

Q7:
Usar metal preferido como información para accesorios.

No cambiar arbitrariamente la preferencia del usuario.

Q8:
Debe influir fuertemente en la estética de los looks.

Q9:
Debe determinar qué looks generar y su prioridad.

Q10:
Debe utilizarse como referencia estética.

11. REPORT Y PDF
==================================================

ESTO ES CRÍTICO.

Debe existir UN SOLO resultado final:

const finalProfile = ...

Ese mismo objeto debe alimentar:

Report(finalProfile)

y

generatePdf(finalProfile)

No hacer:

Report → vuelve a analizar

PDF → vuelve a analizar

Debe ser:

GPT
 ↓
finalProfile
 ↓
 ├── Report
 └── PDF

Por lo tanto, si Report dice:

"Otoño Profundo"

el PDF debe decir exactamente:

"Otoño Profundo"

Si Report dice:

"Primavera Clara"

el PDF debe decir exactamente:

"Primavera Clara"

Los colores, silueta, estilo, presupuesto, recomendaciones y looks deben coincidir.
